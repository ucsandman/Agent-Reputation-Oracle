# ERC-8004 Feedback Importer

Read-only indexer that pulls ERC-8004 (Trustless Agents) Reputation Registry feedback from
chain into this oracle's event log, so the scoring engine has real data on day one.

## What it does

1. `eth_getLogs` in 5000-block chunks for `NewFeedback` on the Reputation Registry.
2. Derives the oracle agent id from the ERC-721 token id (see "Agent identity" below)
   and reads `ownerOf(agentId)` on the Identity Registry only to drop self-feedback.
   Feedback for a burned or unregistered token id is skipped.
3. Maps each log to an `attestation` event (`src/erc8004/map.ts`) and appends it directly
   to the `EventLog`. Self-feedback (client == agent owner) is skipped.
4. Stores the last indexed block in an `erc8004_cursor` table in the same SQLite file, so
   a re-run resumes where it stopped.

It bypasses `POST /reputation/event` and writes to the event log directly. The API's
EIP-712 verification is unchanged and still applies to everything submitted over HTTP.

## Running

```bash
npm run index:erc8004
```

Reads env from `.env` (via `tsx --env-file`). Re-running is safe: `appendEvent` is
`INSERT OR IGNORE` on a deterministic id, so replaying a block range imports 0 and
skips everything already stored.

## Environment variables

| Var | Required | Meaning |
|-----|----------|---------|
| `ERC8004_RPC_URL` | yes | JSON-RPC endpoint for the chain being indexed |
| `ERC8004_CHAIN_ID` | yes | Numeric chain id (8453 Base, 1 Ethereum, 84532 Base Sepolia, 11155111 Sepolia) |
| `ERC8004_REPUTATION_REGISTRY` | yes | Reputation Registry address (no default — see table below) |
| `ERC8004_IDENTITY_REGISTRY` | yes | Identity Registry address (no default) |
| `ERC8004_FROM_BLOCK` | no | First block to index when no cursor exists (default `0`) |
| `ERC8004_TO_BLOCK` | no | Last block to index; defaults to chain head. Useful for bounded backfills |
| `DB_PATH` | no | SQLite path (default `./data/reputation.db`) |

## Agent identity

The oracle keys every agent on an `EvmAddress`, but an ERC-8004 agent's durable identity
is the token, not whichever wallet currently owns it. The importer therefore derives a
synthetic address from the token:

```
agentId = checksum(last 20 bytes of keccak256("erc8004:<chainId>:<identityRegistry lowercase>:<tokenId>"))
```

`erc8004AgentId()` in `src/erc8004/map.ts` reproduces it. Rotating the owner key or
transferring the token keeps the same agent id and therefore the same reputation history.
The `agents.metadata` row stores `{ erc8004: { chainId, identityRegistry, tokenId, owner } }`
so the explorer can show the token behind the address, and `owner` is the owner at last import.

## Provenance convention

Imported events are witnessed by the chain, not by an EIP-712 signature. The `proof`
object records where the event came from:

| Field | Value |
|-------|-------|
| `domain` | `erc8004:<chainId>` — marks the event as chain-imported, not oracle-signed |
| `signer` | `clientAddress` from the `NewFeedback` log (the feedback author) |
| `signature` | the transaction hash carrying the feedback log |
| `typedDataHash` | `keccak256(utf8("erc8004:<chainId>:<txHash>:<logIndex>"))` |

`id` is a deterministic UUID v5 over that same `erc8004:<chainId>:<txHash>:<logIndex>`
string. The literal string is not used as the id because `ReputationEventSchema` requires
`id` to be a UUID; v5 keeps the id deterministic (idempotent re-runs) without loosening
the schema. `feedbackSourceKey()` in `src/erc8004/map.ts` reproduces the raw key.

### Field mapping

| On-chain | Event |
|----------|-------|
| `agentId` (token id) | `agentId` via `erc8004AgentId()` (see "Agent identity") |
| `ownerOf(agentId)` | self-feedback check only; recorded in `agents.metadata.erc8004.owner` |
| `clientAddress` | `sourceAgentId` and `proof.signer` |
| block timestamp | `timestamp` (ISO 8601) |
| `value` / `valueDecimals` | `data.confidence` |
| `tag1 tag2 feedbackURI` | `data.comment` (space-joined, truncated to 1000 chars) |
| — | `eventType: 'attestation'`, `data.category: 'reliability'` |

### Score normalization

ERC-8004 leaves the scale of `value` to the publisher: the spec's own examples range from
`1` decimals `0` (a binary "reachable" signal) to `87` decimals `0` (87/100 quality) to
`9977` decimals `2` (99.77% uptime). Normalization is therefore a heuristic:

```
raw = value / 10 ** valueDecimals
confidence = raw <= 1 ? clamp(raw, 0, 1) : clamp(raw / 100, 0, 1)
```

Raw values at or below 1 are read as unit fractions, above 1 as a 0-100 scale. Negatives
and non-finite values become 0. If a publisher uses another range, add a per-tag scale
lookup keyed on `tag1`.

## ABI

Verified by decoding real Base mainnet logs (topic0
`0x6a4a61743519c9d648a14e6493f47dbe3ff1aa29e7785c96c8326a205e58febc`):

```solidity
event NewFeedback(
  uint256 indexed agentId, address indexed clientAddress, uint64 feedbackIndex,
  int128 value, uint8 valueDecimals, string indexed indexedTag1, string tag1,
  string tag2, string endpoint, string feedbackURI, bytes32 feedbackHash
);

function ownerOf(uint256 tokenId) external view returns (address); // Identity Registry (ERC-721)
```
